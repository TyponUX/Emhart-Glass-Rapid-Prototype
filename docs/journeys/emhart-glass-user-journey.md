# Emhart Glass User Journey

**Source:** [Customer Journey Map](customer-journey-map.pdf)
**Scope:** End-to-end customer journey for reporting equipment problems, finding guidance, requesting parts or services, tracking progress, and closing the request.

## Journey overview

1. Recognise a problem
2. Discovery
3. Diagnose the problem
4. Review guidance
5. Identify support
6. Search and filter
7. Read content
8. Validate the part
9. Escalate and request support
10. Check availability
11. Check price
12. Request a quotation
13. Awaiting
14. Receive quote
15. Place order
16. Track updates
17. View order history or overview
18. Order or service complete
19. Close request
20. Provide feedback

## Journey map

### 1. Recognise: problem occurs

**Moment:** The user notices a problem with a machine, process, or piece of equipment.

**Tasks**
- Notice a problem
- Report the problem
- Assess impact and urgency

**Steps**
- Observe the machine, process, or equipment.
- Identify unusual behaviour, an error, or a disruption.
- Note what happened and when it started.
- Open the support or service request area.
- Describe the problem and affected equipment.
- Add photos, error codes, or other evidence.
- Submit the report.
- Determine whether production is stopped, slowed, or unaffected.
- Identify how many machines or processes are affected.
- Select the appropriate urgency level.
- Decide whether immediate support is required.

**MVP note:** Recognise is marked as not MVP in the source map.

### 2. Discovery

**Task:** Diagnose the problem.

**Steps**
- Enter the symptoms, error message, or error code.
- Select the affected machine or equipment.
- Answer the diagnostic questions.
- Review the possible causes.
- Select the most likely cause.

**Task:** Review guidance.

**Steps**
- Open the recommended troubleshooting guidance.
- Read the instructions and safety information.
- Check whether the guidance applies to the equipment.
- Follow the recommended checks or actions.

**MVP note:** Discovery is marked as not MVP in the source map.

### 3. Identify information and support

**Task:** Search and filter.

**Steps**
- Open the documentation area.
- Search for the machine, product, component, or part.
- Filter results by equipment or document type.
- Select the relevant document.

**Task:** Read content.

**Steps**
- Open the selected document.
- Confirm that it matches the correct equipment and revision.
- View SOPs.
- View machine drawings.
- Read the relevant instructions or technical information.
- Identify the information needed to solve the problem.

**Task:** Validate part.

**Steps**
- Search by part number, equipment, or machine.
- Review the available matching parts.
- Check the part description and technical details.
- Confirm compatibility with the equipment.
- Select the required part.

**Task:** Escalate and support.

**Steps**
- Confirm that the recommended guidance did not solve the problem.
- Select the option to request further help.
- Describe what has already been checked.
- Attach relevant photos, documents, or error information.
- Submit the escalation.

### 4. Request parts or services

**Task:** Check availability.

**Steps**
- Enter the part number and required quantity.
- Select the delivery location.
- Review the stock status.
- Check the estimated lead time.
- Confirm that the part can be supplied when needed.

**Task:** Check price.

**Steps**
- Open the part price information.
- Enter the required quantity.
- Review the unit price and total price.
- Check shipping, taxes, or additional costs.
- Confirm that the price is acceptable.

**Task:** Request quotation.

**Steps**
- Add the required parts to the quote request.
- Enter the quantity and delivery location.
- Add supporting information or special requirements.
- Submit the quote request.
- Save the quote-request number.

**Task:** Awaiting.

After submission, the user should see explicit status stages:

- Request received
- Under review
- Pending clarification

**Moment that matters:** The user needs reassurance that the request has been received and knows what happens next.

**Task:** Receive quote.

**Steps**
- Open the quote notification.
- Review the quoted parts and quantities.
- Check prices, delivery dates, and additional costs.
- Compare the quote with the original request.
- Accept the quote or request clarification.

**Task:** Place order.

**Steps**
- Confirm delivery and billing details.
- Add purchase-order or customer information.
- Review the complete order.
- Submit the order.
- Save the order number.

### 5. Track updates

**Task:** Get notification.

**Steps**
- Open the order or service-request area.
- Search for the order or request number.
- Review the current status.
- Check shipment, delivery, or service updates.
- Respond to any outstanding action or information request.

**Task:** View order history or overview.

**Steps**
- Open the order, request, or communication history.
- Search or filter by date, equipment, or order number.
- Select the relevant previous record.
- Review earlier orders, requests, messages, or resolutions.
- Reuse relevant information if needed.

**Task:** Stay informed.

**Steps**
- Read the latest messages and attachments.
- Check whether a response or action is required.
- Reply with the requested information.
- Mention colleagues or stakeholders when their input is needed.

### 6. Resolve and close

**Task:** Order or service complete.

**Steps**
- Open the order confirmation.
- Check the order number.
- Verify the parts, quantities, and prices.
- Share the confirmation with the relevant team.

**Task:** Close request.

**Steps**
- Confirm that there are no remaining issues or open actions.
- Add final comments if required.
- Select the option to close the request.
- Confirm the closure.

**Task:** Provide feedback.

**Steps**
- Open the feedback form.
- Rate the service or support experience.
- Describe what worked well or could be improved.
- Submit the feedback.

## MVP boundaries

The source journey map marks these areas as **not MVP**:

- Recognise / problem occurs
- Discovery

The MVP journey therefore starts with identifying information and support, then covers part validation, availability, quotation, ordering, tracking, completion, closure, and feedback.

## Product implications

- Provide a clear status trail after every submitted request.
- Make equipment, machine, revision, part, and document relationships visible.
- Support search by part number, equipment, machine, order number, and request number.
- Show stock, lead time, price, delivery, and service status in one place.
- Preserve order, request, communication, and resolution history.
- Make escalation possible without losing the user's previous troubleshooting context.
- Keep the next required action visible during awaiting and tracking stages.
